# 外部资源接入执行路径

本文档将《外部资源接入与治理实施方案》拆分为可连续执行的开发路径。每个阶段都应在前一阶段稳定后开始；不要跳过安全、来源和任务模型，直接实现通用网页抓取。

关联方案：[外部资源接入与治理实施方案](./外部资源接入与治理实施方案.md)

## 1. 执行原则

- 优先接入官方 API、Feed 和手工外链，最后才实施站点专用采集器。
- 资源、外部地址、来源、许可和本地文件必须分开建模。
- 外部网络请求只能在异步任务中运行，HTTP API 只创建任务并返回任务 ID。
- 所有远端 URL 都必须先通过 SSRF 防护和来源策略校验。
- 默认只保存链接与元数据；下载或网页归档必须经过显式策略许可。
- 每一阶段完成后运行测试、类型检查、构建，并保留可回退的数据迁移。

## 2. 推荐执行顺序

```text
P0 基线确认
  -> P1 领域模型与迁移
  -> P2 URL 安全与导入任务框架
  -> P3 外链元数据导入和前端管理
  -> P4 来源、许可与链接健康检查
  -> P5 受控直链下载与文件处理复用
  -> P6 官方 API 连接器与增量同步
  -> P7 独立 Worker、可靠队列与站点专用采集
```

P1 至 P3 构成最小可用版本。完成 P3 后，系统已经能安全地把外部链接作为一类资源进行管理、搜索和展示。

## 3. P0：基线确认

### 目标

确认当前项目可正常运行，明确现有上传、处理和资源详情的边界，避免在脏基线上叠加新模块。

### 工作项

- [ ] 阅读 `apps/api/prisma/schema.prisma`，确认 `Resource`、`ResourceFile` 和 `ProcessingJob` 的现有关系。
- [ ] 阅读上传模块和处理模块，确认原文件创建后如何进入处理队列。
- [ ] 确认当前 SQLite 数据库仅用于开发；生产演进目标为 PostgreSQL。
- [ ] 记录现有工作区中与本功能无关的未提交改动，不对其进行还原或格式化。
- [ ] 运行现有质量检查并记录基线结果。

### 验证命令

```bash
pnpm test
pnpm typecheck
pnpm build:api
pnpm build:web
```

### 完成判定

- 当前功能的失败项已记录，且不由本次功能引入。
- 明确了新增模块不应修改上传主流程的哪些行为。

## 4. P1：领域模型与数据库迁移

### 目标

让系统能够表达“只有外部链接、尚未下载文件”的资源，并建立来源、许可和导入任务的最小关系。

### 前置条件

- P0 完成。
- 已确认 SQLite 和 PostgreSQL 的迁移策略。

### 代码位置

| 工作内容 | 目标位置 |
| --- | --- |
| 枚举和共享 DTO 类型 | `packages/shared-types/src/` |
| Prisma 模型和迁移 | `apps/api/prisma/` |
| 公共常量 | `apps/api/src/common/constants/` |

### 工作项

- [ ] 在共享类型中新增 `AcquisitionMode`、`SourceType`、`LocatorType`、`IngestionJobType`、`IngestionJobStatus`、`LicenseStatus`。
- [ ] 为 `Resource` 增加 `acquisitionMode`、`sourceId`、`licenseId`、`licenseStatus`、`externalCreatedAt`、`externalUpdatedAt`。
- [ ] 新增 `Source` 模型，包含来源策略、限流配置、是否启用和非敏感连接器配置。
- [ ] 新增 `ResourceLocator` 模型，包含 URL、规范化 URL、外部 ID、HTTP 探测状态、ETag 与检查时间。
- [ ] 新增 `ResourceProvenance` 模型，保存原始地址、作者、发布者、许可、连接器版本与采集时间。
- [ ] 新增 `License` 模型，支持 SPDX 标识及来源侧自定义许可信息。
- [ ] 新增 `IngestionJob` 模型，独立于 `ProcessingJob`。
- [ ] 建立唯一约束和索引：`Source.slug`、来源内 `externalId`、`canonicalUrl`、任务 `idempotencyKey`、任务状态与计划执行时间。
- [ ] 编写迁移并更新 seed；至少写入 `unknown` 许可记录。
- [ ] 在空数据库和含有现有资源的开发数据库上分别验证迁移。

### 数据兼容规则

- 现有上传资源的 `acquisitionMode` 迁移为 `local_upload`。
- 已有 `source`、`author`、`licenseNote` 不删除，作为历史兼容字段。
- 外链资源允许没有 `ResourceFile`；本地上传资源必须至少有一个 `ResourceFile(fileRole = original)`。
- 未知许可统一为 `licenseStatus = unknown`，不推断为可下载或可再分发。

### 完成判定

- 能用 Prisma Client 创建没有 `ResourceFile`、但具有 `ResourceLocator` 的资源。
- 现有文件上传、资源列表和处理任务查询不受影响。
- 迁移可在干净环境重复执行。

## 5. P2：URL 安全与导入任务框架

### 目标

建立安全地处理外部 URL 的公共能力，以及可重试、可观测的异步导入任务骨架。

### 前置条件

- P1 完成且数据库迁移已应用。

### 代码位置

| 工作内容 | 目标位置 |
| --- | --- |
| 导入模块 | `apps/api/src/modules/ingestion/` |
| 来源模块 | `apps/api/src/modules/source/` |
| URL 解析与网络安全服务 | `apps/api/src/common/security/` |
| 导入 DTO | `apps/api/src/modules/ingestion/dto/` |

### 工作项

- [ ] 创建 `IngestionModule`，包含 Controller、Service、Repository、Scheduler 接口和 Connector Registry。
- [ ] 创建 `SourceModule`，仅实现内部来源配置 CRUD。
- [ ] 实现 URL 规范化：校验协议、移除无意义 fragment、规范化主机名、保留语义必要的 query。
- [ ] 实现 URL 安全校验：仅允许 `http`/`https`，拒绝 `file:`、`data:`、`ftp:` 等协议。
- [ ] 实现 DNS 与 IP 地址校验：拒绝回环、私网、链路本地、保留地址和云元数据地址。
- [ ] 实现重定向安全校验：每次跳转均重新校验目标 URL 与解析 IP。
- [ ] 限制最大重定向数、连接超时、响应超时、响应头大小与探测响应体大小。
- [ ] 实现 `IngestionJob` 创建、认领、成功、失败、取消和重试状态转换。
- [ ] 以 `sourceId + jobType + normalizedInput` 生成幂等键，重复请求返回已存在的活跃任务。
- [ ] 记录结构化错误码，例如 `url_not_allowed`、`ssrf_blocked`、`source_disabled`、`rate_limited`、`remote_unavailable`。
- [ ] API 只负责创建任务，不在请求线程请求远端页面或下载文件。

### 必须测试的场景

- [ ] 非 HTTP(S) 协议被拒绝。
- [ ] `localhost`、`127.0.0.1`、`::1`、私网和链路本地地址被拒绝。
- [ ] 合法公网 URL 可以创建导入任务。
- [ ] 重定向到私网地址时被拒绝。
- [ ] 相同请求只产生一个活跃任务。
- [ ] 可重试错误和不可重试错误走不同状态转换。

### 完成判定

- 已能安全创建 `import_url` 任务并通过查询接口看到其状态。
- 所有网络边界规则被单元测试覆盖；测试不访问真实内网。

## 6. P3：外链元数据导入与前端管理

### 目标

交付首个用户可见能力：用户粘贴公开 URL 后，系统异步提取元数据，创建可搜索和管理的外链资源。

### 前置条件

- P2 完成。

### 后端工作项

- [ ] 实现 `LinkMetadataConnector`，使用 HTTP 请求获取有限大小的 HTML。
- [ ] 按优先级解析 `canonical`、Open Graph、`title`、description、site name、favicon 和预览图地址。
- [ ] 将页面 URL、canonical URL、预览图 URL 保存为不同的 `ResourceLocator`。
- [ ] 创建 `Resource`，导入模式为 `link_only`，无需创建 `ResourceFile`。
- [ ] 创建 `ResourceProvenance`，记录采集时间、原 URL 和连接器版本。
- [ ] 实现 `POST /api/imports/link`、`GET /api/ingestion/jobs`、`POST /api/ingestion/jobs/:id/retry`。
- [ ] 调整资源列表、详情、搜索与统计查询，使其能处理无 `ResourceFile` 的资源。
- [ ] 对不存在缩略图的外链返回稳定占位状态，不抛出 500 错误。

### 前端工作项

- [ ] 在导航或资源列表中添加“添加链接资源”入口。
- [ ] 表单只要求 URL；标题、标签、分类为可选覆盖值。
- [ ] 提交后显示任务状态，完成后跳转或刷新到资源详情。
- [ ] 资源卡片和详情页显示来源域名、外链图标、许可状态和原始链接。
- [ ] 外链资源不显示本地文件下载、预览或重新处理操作。
- [ ] 对抓取失败显示可重试状态与原 URL，不丢失用户输入。

### 验收场景

1. 用户粘贴一个公开静态页面 URL。
2. API 创建任务并立即返回。
3. Worker/调度器完成元数据提取。
4. 资源列表显示标题、来源域名和外链状态。
5. 用户可为外链添加标签、分类、收藏和集合。
6. 资源详情可跳转原网站，不能错误地请求本地文件预览。

### 完成判定

- P3 可以作为第一个对外可试用的版本。
- 当前本地上传流程、缩略图处理、资源详情和批量操作仍通过既有测试。

## 7. P4：来源、许可与链接健康检查

### 目标

让来源政策成为可执行规则，并能识别失效外链与不明确的许可。

### 工作项

- [ ] 完成 `Source` 的管理页面和 API：启用状态、允许导入模式、限流、是否需要人工审核。
- [ ] 提供最小许可证目录，并允许记录来源原始许可文本和 URL。
- [ ] 资源详情页展示许可状态、署名要求、作者和发布者。
- [ ] 对 `mirror_file` 和 `archive_snapshot` 增加策略门禁：来源禁用、许可未知、需审核时不得自动创建任务。
- [ ] 实现 `check_locator` 任务，使用 `HEAD` 或受限 `GET` 检查 HTTP 状态、ETag、最后修改时间和内容类型。
- [ ] 定时检查外链，使用指数退避；连续失败后标记 `unavailable`，不删除资源记录。
- [ ] 支持手动更新来源信息和重新检查链接。

### 完成判定

- 所有外链资源都能显示来源和许可状态。
- 来源被禁用后，无法新建导入或下载任务。
- 失效链接可见、可筛选、可重试，且不会破坏资源列表。

## 8. P5：受控直链下载与文件处理复用

### 目标

只对允许镜像的资源下载文件，并将其接入既有 `ResourceFile` 与处理流水线。

### 前置条件

- P4 完成。
- 已为下载内容定义总容量、单文件大小、文件类型和扫描策略。

### 工作项

- [ ] 实现 `DirectDownloadConnector`，仅接受已通过策略检查的下载定位器。
- [ ] 下载前探测 Content-Length、Content-Type 和最终 URL；超过限制则终止任务。
- [ ] 流式下载到临时对象，不将完整文件读入内存。
- [ ] 用文件魔数检测最终 MIME，拒绝与策略不匹配的文件。
- [ ] 计算 SHA-256，复用现有重复检测与 `duplicateOfId` 机制。
- [ ] 将成功文件写入 `ResourceFile(fileRole = original)`，并创建现有元数据、缩略图和文本提取任务。
- [ ] 加入文件扫描状态；扫描未通过或尚未执行时，禁止内联预览。
- [ ] 对压缩文件限制压缩比、条目数和解压后总大小。
- [ ] 失败时清理临时对象，保留导入任务与失败原因。

### 验收场景

- [ ] 允许的图片直链下载后生成原件和缩略图。
- [ ] 远端文件大于上限时，任务失败且不产生孤立文件。
- [ ] 下载过程中连接中断后可按策略续传或安全重试。
- [ ] 相同内容再次下载时识别 hash 重复。
- [ ] MIME 伪装、压缩炸弹和超大响应不会进入预览链路。

### 完成判定

- 直链下载是显式动作，不是链接导入的默认副作用。
- 已下载资源与本地上传资源可使用同一套派生文件、搜索和详情能力。

## 9. P6：官方 API 连接器与增量同步

### 目标

使用一个真实官方 API 验证连接器、凭据、限流与幂等同步模型。

### 推荐首个来源

GitHub REST API。它具有清晰的 API、分页、ETag、速率限制和稳定外部 ID，适合验证通用同步能力。

### 工作项

- [ ] 实现 `GitHubConnector`，初期只导入仓库、Release 或 Release assets 中的一类资源。
- [ ] 使用环境变量或密钥服务注入 Token，不在数据库明文、日志或 API 返回值中保存 Token。
- [ ] 支持分页、`ETag`/`If-None-Match` 和 `Retry-After`。
- [ ] 按 `sourceId + externalId` upsert 资源与定位器。
- [ ] 将 API 许可、作者和发布时间映射到来源记录；未知时保持 `unknown`。
- [ ] 提供手动同步和定时同步；每次只处理新增或变更项目。
- [ ] 为 401、403、404、429、5xx 分别定义任务错误码和重试策略。

### 完成判定

- 重复同步不会重复创建资源。
- 达到 API 限额时会延迟重试，不会立即循环请求。
- 禁用来源或撤销 Token 后任务安全失败，既有资源仍可浏览。

## 10. P7：独立 Worker、可靠队列与站点专用采集器

### 目标

在并发、稳定性和安全隔离达到要求后，再支持动态站点和站点专用采集。

### 触发条件

满足以下任一条件后开始本阶段：

- 导入任务执行时间经常超过 API 请求生命周期。
- 同时存在多个来源同步、下载或链接检查任务。
- 需要 Playwright 执行 JavaScript。
- 需要在 API 重启后可靠恢复未完成任务。

### 工作项

- [ ] 实现 `apps/worker` 的独立启动、健康检查、优雅停机和任务认领逻辑。
- [ ] 迁移到 PostgreSQL + Redis/BullMQ 或同等可靠的队列方案。
- [ ] 将导入任务与文件处理任务分队列，分别设置并发、超时和来源限流。
- [ ] 对静态页面继续使用普通 HTTP 客户端；只有批准的连接器可使用 Playwright。
- [ ] Playwright Worker 使用受限网络、资源配额、超时和独立临时目录。
- [ ] 每个站点专用连接器必须附带来源配置、条款/许可说明、fixture 测试、限流参数和一键禁用开关。
- [ ] 为队列堆积、来源故障、下载失败率和任务耗时建立监控。

### 完成判定

- API 和 Worker 可独立部署、独立扩缩容。
- API 重启后未完成导入任务不会丢失或重复执行。
- 一个来源异常不会阻塞其他来源。
- 任一站点采集器可以独立禁用，无需重新部署。

## 11. 每阶段交付检查

在每个阶段合并前执行：

```bash
pnpm test
pnpm typecheck
pnpm lint
pnpm build:api
pnpm build:web
```

同时检查：

- [ ] 数据库迁移可在新库和已有开发库上运行。
- [ ] 新增接口已进行 DTO 验证，错误码可被前端处理。
- [ ] 不记录或返回密钥、Cookie、Authorization 头和签名 URL。
- [ ] 外部网络请求均有超时、大小限制和可观测错误。
- [ ] 新增前端状态在移动端与桌面端均不会出现文本溢出或操作不可达。
- [ ] 文档同步更新：接口、环境变量、部署要求和来源策略。

## 12. 最小版本范围

第一个开发迭代只实施 P1、P2 和 P3，交付内容如下：

- 用户可添加公开 HTTP(S) 链接。
- 后端异步提取网页标题、描述、规范链接和 Open Graph 图片。
- 外链作为资源出现在资源列表、搜索、分类、标签和集合中。
- 资源详情可打开原链接，并显示来源域名和导入状态。
- 系统拒绝私网、危险协议和不安全重定向。
- 不下载远端文件、不执行 Playwright、不实现通用网页爬虫。

该范围验证产品价值和架构方向，风险、实现成本和法律边界均处于可控状态。
