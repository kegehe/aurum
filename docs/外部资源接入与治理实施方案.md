# 外部资源接入与治理实施方案

## 1. 目标

将当前以本地上传文件为中心的资源管理平台，扩展为能够从多个合规来源登记、导入、同步和管理资源的平台。

本方案支持以下接入方式：

- 手工登记外部链接，并提取网页元数据。
- 通过官方 API、RSS、Atom 或 JSON Feed 导入资源元数据。
- 下载用户明确指定且允许下载的公开直链。
- 对经过来源评估和单独配置的网站进行受控采集。

本方案的原则是：资源的发现、登记、下载和归档是四个独立能力。系统默认保存来源与元数据，不默认复制远端内容。

## 2. 非目标

第一阶段不实现以下能力：

- 对任意网站进行无差别抓取或绕过访问限制。
- 绕过付费墙、登录、验证码、DRM 或反自动化机制。
- 自动使用用户浏览器 Cookie、会话或私有访问令牌下载内容。
- 在未确认许可或来源规则前自动镜像第三方文件。
- 多租户、细粒度权限、公开分享链接或完整审计系统。

## 3. 核心决策

### 3.1 资源不等于文件

现有 `Resource` 代表已入库文件。扩展后，`Resource` 代表可管理的资产；它可以只有外部链接，也可以同时关联一个或多个本地文件。

`ResourceFile` 仍只记录本地原件、缩略图、预览、转码和文本提取产物。外部链接不应伪装成 `ResourceFile`。

### 3.2 导入模式

每次导入必须明确选择一种模式：

| 模式 | 含义 | 默认适用场景 | 是否产生本地原件 |
| --- | --- | --- | --- |
| `link_only` | 保存链接、元数据和预览信息 | 参考资料、商业站资源 | 否 |
| `metadata_only` | 从 API 或 Feed 保存结构化元数据 | 官方素材库、开放数据目录 | 否 |
| `archive_snapshot` | 保存网页快照或允许归档的衍生内容 | 有归档权的页面、内部文档 | 是，可选 |
| `mirror_file` | 下载并保存远端原始文件 | 自有资产、开源或明确允许备份的资源 | 是 |

默认模式为 `link_only`。`archive_snapshot` 与 `mirror_file` 必须通过来源策略校验，并由用户显式确认。

### 3.3 接入分层

```text
Web UI / Internal API
        |
  ImportRequest
        |
  IngestionJob ---- Connector Registry
        |                 |- LinkMetadataConnector
        |                 |- OfficialApiConnector
        |                 |- FeedConnector
        |                 |- DirectDownloadConnector
        |                 `- SiteSpecificConnector
        |
Resource + ResourceLocator + ResourceProvenance + ResourceFile
        |
ProcessingJob: metadata / thumbnail / OCR / hash / scan / index
```

导入任务与现有 `ProcessingJob` 分离：

- `IngestionJob` 负责发现、请求外部服务、下载、同步和链接检查。
- `ProcessingJob` 只处理已入库的本地文件及其派生物。

## 4. 数据模型

以下是目标数据模型。字段命名与现有 Prisma 风格保持一致，实施时通过迁移落库。

### 4.1 Resource 扩展

为 `Resource` 新增：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `acquisitionMode` | String | 四种导入模式之一，默认 `local_upload` |
| `sourceId` | String? | 主来源配置 ID |
| `licenseId` | String? | 标准化许可 ID |
| `licenseStatus` | String | `unknown`、`verified`、`restricted`、`rejected` |
| `externalCreatedAt` | DateTime? | 资源在来源侧的创建时间 |
| `externalUpdatedAt` | DateTime? | 资源在来源侧的更新时间 |

保留现有 `source`、`author`、`licenseNote` 字段，以兼容已有数据；新功能优先使用下面的结构化表。

### 4.2 Source

来源站点或服务的配置。它描述政策和连接方式，不保存资源本身。

| 字段 | 说明 |
| --- | --- |
| `id`、`name`、`slug` | 标识与显示名称 |
| `baseUrl` | 来源站点或 API 根地址 |
| `connectorType` | `link_metadata`、`github`、`rss`、`custom` 等 |
| `enabled` | 是否允许新任务使用 |
| `allowedModes` | 可用导入模式集合 |
| `termsUrl`、`robotsUrl` | 服务条款和抓取规则地址 |
| `defaultLicenseId` | 来源默认许可，可为空 |
| `rateLimitPerMinute`、`maxConcurrency` | 每来源限流 |
| `requiresReview` | 是否需要人工确认才允许镜像 |
| `config` | 非敏感连接器配置 JSON |
| `lastSyncedAt` | 最近成功同步时间 |

敏感凭据不存入 `config`。开发环境可使用环境变量；生产环境应使用密钥管理服务或加密凭据表。

### 4.3 ResourceLocator

一个资源可以有多个访问地址，例如原始页面、下载地址和镜像地址。

| 字段 | 说明 |
| --- | --- |
| `resourceId` | 所属资源 |
| `sourceId` | 来源配置，可为空 |
| `locatorType` | `page`、`download`、`api`、`mirror`、`preview` |
| `url` | 用户输入或来源返回的地址 |
| `canonicalUrl` | 规范化后的主地址，用于去重 |
| `externalId` | 来源系统中的稳定 ID |
| `isPrimary` | 资源默认访问地址 |
| `httpStatus`、`contentType`、`contentLength` | 最近探测结果 |
| `etag`、`lastModified` | 增量同步与变更检测标识 |
| `lastCheckedAt`、`lastError` | 可用性检查状态 |

约束：同一来源内 `externalId` 唯一；`canonicalUrl` 建立索引；每个资源最多一个 `isPrimary = true` 的地址。

### 4.4 ResourceProvenance

记录资源如何进入系统，确保资源可追溯和可下架。

| 字段 | 说明 |
| --- | --- |
| `resourceId`、`sourceId`、`ingestionJobId` | 关联关系 |
| `connectorType`、`connectorVersion` | 使用的连接器及版本 |
| `originalUrl` | 采集时的原始地址 |
| `publisher`、`authorName`、`authorUrl` | 署名信息 |
| `licenseText`、`licenseUrl`、`attributionText` | 来源侧许可与署名要求 |
| `capturedAt` | 采集时间 |
| `rawMetadata` | 最小化保存的原始响应 JSON，避免存储认证信息 |

### 4.5 License

许可证采用结构化表，支持 SPDX 标识和来源自定义条款。

| 字段 | 说明 |
| --- | --- |
| `id`、`spdxId`、`name` | 标准标识与名称 |
| `url`、`text` | 许可原文或链接 |
| `allowsCommercialUse`、`allowsRedistribution`、`allowsDerivatives` | 使用限制 |
| `requiresAttribution`、`shareAlike` | 义务 |

### 4.6 IngestionJob

导入与同步任务。

| 字段 | 说明 |
| --- | --- |
| `id`、`sourceId`、`resourceId` | 关联关系 |
| `jobType` | `import_url`、`sync_source`、`download_file`、`check_locator`、`capture_page` |
| `status` | `pending`、`processing`、`completed`、`failed`、`canceled` |
| `request`、`result` | 脱敏后的请求参数与结果摘要 JSON |
| `idempotencyKey` | 防止重复提交 |
| `retryCount`、`nextRunAt`、`startedAt`、`finishedAt` | 执行状态 |
| `errorCode`、`errorMessage` | 可观察的失败信息 |

## 5. 连接器契约

每个连接器实现统一接口，连接器只负责获取和规范化外部信息，不直接写数据库。服务层负责策略校验、持久化、任务状态和审计。

```ts
export interface ResourceConnector {
  readonly type: string;

  canHandle(input: ImportInput, source: SourceConfig): boolean;
  inspect(input: ImportInput, context: ConnectorContext): Promise<RemoteResource>;
  download?(input: DownloadInput, context: ConnectorContext): Promise<DownloadStream>;
  sync?(cursor: string | null, context: ConnectorContext): Promise<SyncPage>;
}
```

`RemoteResource` 至少应包含：

- `externalId`、`canonicalUrl`、`title`、`description`。
- `author`、`publisher`、`license`、`createdAt`、`updatedAt`。
- 可选 `previewUrl`、`downloadUrl`、MIME 类型、预估大小和 ETag。

### 5.1 首批连接器

按下列顺序实现，避免一开始投入通用爬虫：

1. `LinkMetadataConnector`：提取 HTML `title`、Open Graph、favicon 和 canonical URL。
2. `DirectDownloadConnector`：仅下载通过来源策略校验的明确直链。
3. `GitHubConnector`：使用 GitHub 官方 REST API 导入 release、仓库文件或仓库元数据。
4. `FeedConnector`：导入 RSS、Atom 和 JSON Feed。
5. `SiteSpecificConnector`：只为已评估的网站编写独立实现。

## 6. 来源策略与合规控制

### 6.1 来源准入

每个 `Source` 在启用前必须配置：

- 来源名称、域名/API 根地址、服务条款 URL。
- 是否提供官方 API、Feed 或公开导出。
- 允许的导入模式。
- 默认许可与人工复核要求。
- 访问频率、并发数、重试上限。
- 是否允许保存文件副本或网页快照。

优先级为：官方 API > Feed/导出 > 手工链接登记 > 受控网页采集。

### 6.2 下载前检查

在生成 `mirror_file` 或 `archive_snapshot` 任务前，系统必须确认：

1. 来源策略允许该模式。
2. 资源许可允许保存副本，或操作者完成“我拥有保存权”的显式确认。
3. URL 通过 SSRF 和协议校验。
4. MIME 类型与文件大小符合系统限制。
5. 不需要绕过认证、验证码、付费墙、DRM 或技术限制。

### 6.3 robots 与服务条款

采集器在访问网站前读取并缓存 `robots.txt`，并按 RFC 9309 处理可适用规则。

`robots.txt` 不是内容复制授权。站点服务条款、版权许可和访问控制优先级更高。发现禁止自动访问、许可证不清楚或存在访问限制时，任务应进入 `failed` 或 `requires_review`，而不是尝试绕过。

## 7. 安全要求

所有外部 URL 和下载任务必须通过以下控制：

- 仅接受 `http` 与 `https` 协议。
- 拒绝回环、私网、链路本地、保留地址及云元数据地址。
- DNS 解析后校验 IP；每次重定向后重新校验目标地址。
- 限制重定向次数、连接超时、响应超时、最大响应头和最大下载大小。
- 流式写入对象存储，禁止将大文件完整读入内存。
- 使用文件魔数检测 MIME 类型，不仅依赖扩展名和响应头。
- 对 ZIP、RAR、7z、tar 等归档文件执行解压炸弹防护。
- 接入恶意文件扫描前，所有下载内容标记为 `pending_scan`，不提供内联预览。
- HTML、SVG、PDF 等不可信预览通过独立域名、严格 CSP 或沙箱 iframe 隔离。
- 不在日志、任务结果、API 响应或前端页面中泄露带签名 URL、Token、Cookie 和 Authorization 头。

## 8. API 设计

以下为内部 API。鉴权引入前，仅服务于可信内部环境。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/imports/link` | 以 `link_only` 导入 URL 并提取元数据 |
| `POST` | `/api/imports/download` | 创建经策略校验的直链下载任务 |
| `POST` | `/api/imports/sources/:sourceId/sync` | 触发来源增量同步 |
| `GET` | `/api/ingestion/jobs` | 查询导入任务 |
| `POST` | `/api/ingestion/jobs/:id/retry` | 重试可重试任务 |
| `GET` | `/api/sources` | 查询来源配置 |
| `POST` | `/api/sources` | 创建来源配置 |
| `PATCH` | `/api/sources/:id` | 更新、禁用或调整来源策略 |
| `POST` | `/api/resources/:id/locators/check` | 检查外链可用性 |
| `POST` | `/api/resources/:id/mirror` | 将已登记资源镜像为本地文件 |

`POST /api/imports/link` 请求示例：

```json
{
  "url": "https://example.org/assets/sample.png",
  "sourceId": "optional-source-id",
  "categoryId": "optional-category-id",
  "tagIds": ["tag-id"],
  "title": "Optional override"
}
```

接口应立即返回 `IngestionJob`，由前端轮询任务状态。不得在 HTTP 请求中同步执行网页抓取或大文件下载。

## 9. 实施计划

### 里程碑 M1：链接资源基础能力

目标：可以安全地登记外链并在资源库中管理。

- [ ] 扩展共享类型：导入模式、来源类型、定位器类型、导入任务状态、许可状态。
- [ ] Prisma 迁移：创建 `Source`、`ResourceLocator`、`ResourceProvenance`、`License`、`IngestionJob`，扩展 `Resource`。
- [ ] 增加 `IngestionModule`、仓储层和服务层。
- [ ] 实现 URL 规范化、协议限制、DNS/IP 校验和重定向校验。
- [ ] 实现 `LinkMetadataConnector`，解析 title、canonical、Open Graph、描述与预览图。
- [ ] 实现 `POST /api/imports/link`、任务查询与重试接口。
- [ ] Web 增加“添加链接资源”入口、任务状态和外链详情展示。
- [ ] 资源详情页区分“本地文件”和“外部链接”，外链资源不显示本地下载按钮。
- [ ] 为 URL 安全校验、链接导入幂等性、失败重试和元数据映射编写单元测试。

完成标准：用户可登记公开 URL，系统异步提取元数据；外链可被标签、分类和搜索管理；私网 URL、非 HTTP(S) URL 和不安全重定向被拒绝。

### 里程碑 M2：来源与许可治理

目标：每个外部资源具有可追溯来源与明确导入政策。

- [ ] 实现来源 CRUD 和策略校验。
- [ ] 实现许可证种子数据，至少包含常见 SPDX 许可与 `unknown`。
- [ ] 导入时写入 `ResourceProvenance`。
- [ ] 实现资源来源、作者、许可与署名信息的详情展示和筛选。
- [ ] 增加来源禁用开关；禁用后不得创建新任务。
- [ ] 增加链接健康检查任务与过期状态。

完成标准：能追溯资源从何处、何时、通过哪个连接器进入系统；不满足来源策略的镜像任务被拒绝。

### 里程碑 M3：直链下载与文件镜像

目标：合规、可控地将允许的远端文件保存为本地资产。

- [ ] 实现 `DirectDownloadConnector`。
- [ ] 添加下载限额、流式存储、断点续传策略和 hash 校验。
- [ ] 下载成功后创建 `ResourceFile(original)` 并复用现有处理流水线。
- [ ] 将文件扫描状态加入资源状态，未扫描文件不可预览。
- [ ] 加入归档文件与 MIME 校验。
- [ ] 处理重复文件：复用 `sha256`、`duplicateOfId` 和现有重复检测逻辑。

完成标准：允许镜像的直链可稳定下载，错误、大小超限和类型不符均可观察并安全失败；下载后缩略图、元数据和去重流程正常执行。

### 里程碑 M4：官方 API 与增量同步

目标：验证可复用连接器模型。

- [ ] 实现 `GitHubConnector`，使用官方 REST API。
- [ ] 支持 API Token 的安全注入、速率限制、ETag 和分页游标。
- [ ] 支持手动同步与定时增量同步。
- [ ] 同步结果按来源 `externalId` upsert，避免创建重复资源。
- [ ] 保留远端更新时间和同步时间。

完成标准：可对一个 GitHub 来源同步资源元数据；重复同步不产生重复资源；达到 API 限额后任务按退避规则重试。

### 里程碑 M5：独立 Worker 与站点专用采集器

目标：将高延迟、高风险任务迁离 API 进程，并只在需要时引入网页自动化。

- [ ] 将 `apps/worker` 实现为独立可部署服务。
- [ ] 从 SQLite 轮询演进到 PostgreSQL + Redis/BullMQ 或等价可靠队列。
- [ ] 分离导入队列和现有处理队列，分别配置并发和限流。
- [ ] 对静态页面使用 HTTP 客户端，对已批准的动态站点才使用 Playwright。
- [ ] 每个站点专用连接器附带来源策略、测试样例、限流和禁用开关。

完成标准：API 重启不会中断或重复执行已认领任务；单一来源故障不会阻塞其他来源；动态采集能力只能由明确启用的连接器使用。

## 10. 队列与重试

导入任务使用以下规则：

- 幂等：`sourceId + jobType + normalizedInput` 生成 `idempotencyKey`。
- 重试：网络超时、503、429 可重试；4xx 授权失败、许可拒绝、SSRF 拒绝不可自动重试。
- 退避：指数退避并包含随机抖动；读取 `Retry-After` 时优先遵守来源要求。
- 并发：以来源维度控制并发；默认每来源 1 个下载任务和 2 个元数据请求。
- 死信：超过最大重试次数的任务保留错误信息，支持人工检查后重试。
- 可观测性：记录任务耗时、下载字节数、HTTP 状态、来源限流等待时间和失败分类。

## 11. 测试与验收

每个里程碑完成前至少满足：

- [ ] 单元测试覆盖 URL 校验、来源策略、导入模式和任务状态迁移。
- [ ] 集成测试使用本地 HTTP fixture，覆盖重定向、超大响应、错误响应和 HTML 元数据解析。
- [ ] 使用模拟 DNS/HTTP 层验证 SSRF 防护，不依赖真实内网地址。
- [ ] 端到端测试覆盖“粘贴 URL -> 任务完成 -> 资源详情可见”。
- [ ] `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm build:api`、`pnpm build:web` 均通过。
- [ ] 对每个官方 API 连接器记录 API 版本、限流策略、许可字段映射和降级行为。

## 13. 实施起点

下一次开发从 M1 开始，先完成结构化外链资源和安全 URL 校验，不实现网页通用爬取。

建议首个变更集按以下顺序提交：

1. Prisma schema 与 shared types。
2. `IngestionModule`、数据仓储与 URL 安全服务。
3. 链接元数据连接器和导入 API。
4. Web 的添加链接入口和资源详情适配。
5. 单元、集成和端到端测试。
