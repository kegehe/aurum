# 测试与验收清单

## 自动化测试

当前自动化测试集中在后端核心逻辑，运行命令：

```bash
pnpm test
```

覆盖范围：

- 搜索筛选条件构建：
  - 默认排除软删除资源。
  - `includeDeleted` 包含回收站资源。
  - `deletedOnly` 仅返回回收站资源，且优先于 `includeDeleted`。
  - 关键词跨字段搜索。
  - 类型、分类、收藏、大小范围筛选。
  - 默认和显式排序。
- 处理任务：
  - 任务分页列表。
  - 任务统计透传。
  - 失败任务重试。
  - 缺失、已完成、处理中任务的错误重试。
- 批量资源操作：
  - 批量移动分类成功/失败计数。
  - 批量收藏成功/失败计数。
  - 批量软删除成功/失败计数。
  - 批量下载无资源错误。
  - 批量下载 ZIP 流、缺失资源计数和存储读取错误传播。
  - 重新处理资源时创建处理任务并返回 processing 状态。
- 批量 DTO：
  - 空资源列表拒绝。
  - 合法收藏批量 payload 通过。
- 资源服务与仓储：
  - 永久删除、清空回收站的文件/数据库删除顺序。
  - 资源重新处理后的任务入队与处理状态同步。
- 上传：
  - 已删除分类/竞态外键错误的可读报错。
- 外部资源接入：
  - 来源配置 CRUD 与策略门禁。
  - 链接导入任务与 SSRF 防护（SafeUrlService）。
  - Civitai 连接器与定时自动同步（分页游标、幂等 upsert、审核门禁、下载开关）。
  - GitHub 连接器（Release 资产映射、tag 源码包回退、页号游标、ETag/304、速率限制报错、私有仓库鉴权头）。
  - RSS 连接器（RSS 2.0 / Atom / JSON Feed 解析、offset 切片游标、guid isPermaLink、enclosure/media:content 选择、HTML 摘要与内联图预览、重定向逐跳校验、超出大小上限报错）。
  - 页面快照（capture_page 任务：archive_snapshot 策略门禁、HTML 存为 snapshot 派生文件、内容未变复用对象、变化时替换并清理旧对象、页面 locator 健康信息回写、超出大小上限的可读报错）。
  - 派生文件下载端点的角色白名单与 attachment + nosniff 分发（含 /preview 对 HTML/XML 的内联降级防护）。
  - LinkMetadata 提取、LocatorHealthChecker 健康探测调度。
  - 直连下载连接器（重定向逐跳公网校验、file:// 等协议拦截、声明长度与实际字节两级限量、魔数 MIME 与回退、HTML 响应拒绝、下载目录前缀、检查点回调与取消传播、失败清理）。
  - 导入任务仓储与 IngestionScheduler。
- 样式实验室：
  - 样式分析服务、Claude Vision 客户端（mock）、本地降级分析、CSS Tokens 导出。
- AI 配置：
  - 多配置管理、生效项切换、密钥掩码。
- 设计运营台（如实覆盖范围，勿再扩张表述）：
  - 覆盖：token 文档与别名链校验（含别名环、类型不匹配、非法 hex 长度）、
    组件的声明契约（CSS 属性白名单、值语法、伪类与伪元素）、动画文档结构、
    钉住依赖版本的校验与去重、声明解析与对比度门禁（含 alpha 合成与大号文本
    阈值）、CSS/Tailwind/bundle 导出（含缓动曲线与阴影的序列化、依赖递归展开）、
    受控渲染（调用真实 `generateStorageKey`、组件多状态并排、动画胶片帧、
    同输入两次渲染 `artifactHash` 相同）。
  - **未覆盖**：`processNextTask` 的事务编排、发布/恢复的并发路径、候选名额
    与租约的竞态、`deleteCandidate` 的级联与产物回收。这些没有事务替身范式，
    按仓库现状（全部为纯单元测试、无 DB 级测试基建）不写单测，靠下方的
    端到端流程验收。
- 处理任务与临时文件清理工具。
- 进程分工开关（`EXECUTION_ENABLED` 关闭处理执行、`INGESTION_ENABLED` 关闭摄入调度）与 SQLite WAL / busy_timeout 初始化。

## 静态验收

运行命令：

```bash
pnpm --filter @aurum/api typecheck
pnpm --filter @aurum/web typecheck
pnpm lint
pnpm build:api
pnpm build:web
```

验收标准：

- API 与 Web TypeScript 类型检查通过。
- ESLint 无错误。
- API 与 Web 生产构建通过。

## 手动验收流程

以下流程需要启动本地 API 和 Web：

```bash
pnpm dev
```

核心流程：

1. 上传图片资源，确认资源出现在资源库。
2. 打开资源详情，确认基础信息、下载和预览入口可用。
3. 给资源设置分类，确认列表筛选能找到该资源。
4. 在资源库选择多个资源，执行：
   - 全选当前页。
   - 批量移动文件夹。
   - 批量收藏与取消收藏。
   - 批量下载 ZIP。
   - 批量删除到回收站。
5. 进入回收站，恢复资源。
6. 再次删除资源，执行彻底删除。
7. 打开处理任务页，筛选失败任务并执行重试。
8. 在「来源」页分别配置 Civitai、GitHub（填 `owner/repo`）、RSS（Base URL 填 Feed 地址）来源并启用自动同步，确认：列表「同步方式」列显示获取方式、点「开始下载」后资源带来源信息入库、再次同步游标继续推进（GitHub 翻页 / RSS `offset:N` 切片）。
9. 在「添加链接」页导入一个网页链接，确认元数据提取（标题/预览/来源）与 SSRF 拦截生效。
10. 打开一个带页面链接的外部资源详情，点「生成快照」：来源未放行 `archive_snapshot` 时提示被策略拒绝；在来源勾选「允许生成页面快照」后重试，确认文件列表出现「页面快照 text/html」、可「取回」（下载而非在线打开），按钮变为「更新快照」，链接健康里页面一条转为 200。
11. 在「设置 → AI 配置」保存密钥并测试连通性，到「样式实验室」上传图片确认分析结果与导出。
12. 打开仪表盘，确认资源总数、存储占用、失败任务等统计可显示。
13. 设计运营台主流程（**曾经在真实存储下完全跑不通**——渲染器传的两个未注册
    role 会让 `render_validate` 必抛，候选永远停在 `generated`，因此一条都发布不出去。
    回归时优先确认这条）：
    - 新建主题资产，在 code 内容里放 color / space / radius / duration /
      cubicBezier / shadow 六类 token，确认创建成功。
    - 新建组件资产，`schemaVersion` 用 `aurum.component.v2`，`dependencies` 填上
      刚才主题的 documentId 与 versionId，声明里混用别名与字面量
      （如 `padding: "{space.md} {space.lg}"`），确认能创建。
    - 创建草稿 → 手工生成候选 → 点 render-validate，确认候选从 `generated`
      变为 `validated`，且三端预览是**真实效果图**（不是 JSON 文本）。
    - 选择并发布，确认版本号递增；用 `?format=bundle` 取导出，确认 CSS 里
      含 `cubic-bezier(...)`、阴影与 `var(--…)` 变量引用。
    - 再造一个对比度不足的候选（如半透明白字压深色底），确认它**不会**变
      `validated`、发布被拒、卡片上能看到实测对比度与原因。
    - 删除该失败候选，确认可以继续新建候选（名额已释放）。
14. 创建向导（`/design-library`，面向外行的入口；专业流程仍保留在
    `/design-library/review`）：
    - 空库进入，展开「内置配色」装一套（如「靛蓝商务」），确认它变成可选的配色，
      并且回审核台能看到这个主题资产已经是 v2。
    - 在「卡片」分类点一个现成效果（如「玻璃拟态卡片」），确认右侧**立刻**出现
      预览（不走 AI、不用等），且鼠标移到预览上能看到悬停态。
    - 拖动「背景模糊」滑轨，确认预览实时变化；点「圆角」档位切换，确认圆角变。
    - 确认「保存」区显示「规范与对比度检查通过」。
    - 保存并发布，确认提示已发布、版本号从 v1 变成 v2。
    - 故意构造对比度不足的方案（用审核台的 JSON 起点把 `color` 与
      `background-color` 都设成 `#ffffff`，再回 `POST /design/compose/publish`），
      确认返回 `published: false`、带实测比值，且**库里的文档数一个都没多**。
    - 配好 AI 后描述一句（如「做一个毛玻璃卡片」）生成 3 个方案，确认方案带真实
      渲染预览；故意不给 AI 配置密钥时，确认任务**立刻**失败并显示"AI 未配置"，
      而不是长时间停在"运行中"（这是一条真实的回归：`return await` 写成了
      `return`，异常会逃出 try/catch，任务会卡在 running 约 20 分钟）。
    - 粘贴一张图片，确认附加了参考图，且生成的方案确实受其配色影响。
