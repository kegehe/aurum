# 资源管理平台实施任务文档

## 1. 实施范围

本实施文档基于 `docs/resource-platform-plan.md`。

第一版实施范围：

- Next.js 前端
- NestJS 后端
- Prisma
- PostgreSQL
- Redis + BullMQ
- 独立 NestJS Worker
- 本地文件存储
- Sharp 图片处理
- FFmpeg 视频/音频处理
- PDF/文本基础提取
- Docker Compose 本地和单机部署

第一版不实施：

- 多用户登录
- 权限体系
- 对外开放 API
- API Key
- Webhook
- 第三方平台 API 集成
- 审核工作流
- 企业级审计
- AI 自动标签
- 语义搜索
- 3D 在线预览

## 2. 总体实施顺序

1. 阶段一：项目初始化——仓库结构、工程规范、本地基础服务。
2. 阶段二：数据模型与数据库——Prisma 初始化、核心表、枚举、索引、初始化数据。
3. 阶段三：后端 API 基础——NestJS 应用、模块骨架、Repository 与 Service。
4. 阶段四：存储模块——本地存储适配器、文件读写、存储安全。
5. 阶段五：资源上传闭环——上传接口、hash 与去重、基础资源管理。
6. 阶段六：Worker 与异步处理——Worker 基础、元数据识别、图片/视频/音频/文本处理、任务重试。
7. 阶段七：标签、分类、集合——标签管理、分类管理、集合管理。
8. 阶段八：搜索与筛选——基础搜索、结构化筛选、搜索优化。
9. 阶段九：前端基础——前端工程初始化、基础布局、UI 设计规范。
10. 阶段十：前端页面——首页、上传页、资源库、详情页、标签/分类/集合/回收站页面。
11. 阶段十一：批量操作——资源多选、批量编辑、批量下载。
12. 阶段十二：回收站与清理——软删除、彻底删除、一致性检查。
13. 阶段十三：统计看板——基础统计、处理任务统计。
14. 阶段十四：部署与运维——Docker Compose、生产配置、备份任务。
15. 阶段十五：测试与验收——后端测试、Worker 测试、前端验收、端到端验收。
16. 阶段十六：文档补充——开发文档、用户使用说明。

### 3.3 本地基础服务

## 4. 阶段二：数据模型与数据库

### 4.1 Prisma 初始化

- 初始化 Prisma。
- 配置 PostgreSQL 数据源。
- 配置 Prisma Client 输出。
- 建立数据库迁移流程。
- 建立 seed 流程。

验收标准：

- Prisma 可以连接数据库。
- 数据库迁移命令可运行。
- Prisma Client 可在后端使用。

### 4.2 核心表模型

- 创建 `resources` 模型（含 width、height、duration_seconds 冗余字段和 search_vector tsvector 字段）。
- 创建 `resource_files` 模型（含 variant 和 extension 字段）。
- 创建 `tags` 模型。
- 创建 `resource_tags` 模型。
- 创建 `categories` 模型。
- 创建 `collections` 模型。
- 创建 `collection_resources` 模型。
- 创建 `processing_jobs` 模型。

验收标准：

- 所有核心表可以迁移到 PostgreSQL。
- 表关系符合方案文档。
- 资源、文件、标签、分类、集合、任务之间关系可查询。

### 4.3 枚举与状态

- 定义资源类型枚举：image, video, audio, text, document, archive, model3d, font, game_asset, other。
- 定义文件角色枚举：original, thumbnail, preview, extracted_text, transcode。
- 定义资源处理状态枚举（资源级）：pending, processing, completed, failed。
- 定义任务状态枚举（任务级）：pending, processing, completed, failed, canceled。
- 定义任务类型枚举：detect_metadata, generate_thumbnail, generate_video_cover, extract_text, detect_duplicate, cleanup_files, cleanup_temp。

验收标准：

- 代码中不使用随意字符串表示核心状态。
- 数据库字段与业务状态一致。
- 资源级 processing_status 和任务级 status 使用两套独立枚举，不混用。

### 4.4 索引与约束

- 为资源创建时间建立索引。
- 为资源更新时间建立索引。
- 为资源删除时间建立索引。
- 为资源类型建立索引。
- 为资源分类建立索引。
- 为资源 hash 建立索引。
- 为资源处理状态建立索引。
- 为资源收藏状态建立索引。
- 为资源冗余字段 width、height、duration_seconds 建立索引。
- 为资源 search_vector 建立 GIN 索引。
- 为标签名称建立唯一约束。
- 为资源标签关联建立唯一约束。
- 为集合资源关联建立唯一约束。
- 为资源文件 resource_id + file_role + variant 建立唯一约束。
- 为处理任务状态建立索引。
- 为处理任务类型建立索引。

验收标准：

- 常用列表查询可使用索引。
- 重复标签无法创建。
- 同一资源不会重复绑定同一标签。
- 同一集合不会重复加入同一资源。

### 4.5 初始化数据

- 初始化默认分类。
- 初始化常用资源类型配置。
- 初始化上传限制配置。
- 初始化本地开发 seed 数据。

验收标准：

- 新环境启动后具备默认分类。

### 7.1 上传接口

- 实现单文件上传。
- 实现多文件批量上传。
- 实现单文件大小限制（MAX_UPLOAD_SIZE_MB）。
- 实现批量上传总大小限制（MAX_UPLOAD_TOTAL_SIZE_MB）。

- 实现上传失败响应。
- 实现上传成功后资源记录创建。
- 实现上传成功后原文件记录创建。
- 实现上传成功后处理任务创建。

验收标准：

- 用户可以上传单个文件。
- 用户可以批量上传文件。

- 在资源记录中保存 hash。
- 在上传结果中返回重复提示。
- 在资源详情中展示重复提示。

验收标准：

- 相同文件可识别为重复。
- 第一版允许重复保存。
- 重复资源能关联到已有资源。

验收标准：

- 资源可列表展示。

- 资源标题、描述、来源、作者、许可证备注可编辑。
- 资源可下载。
- 资源可删除到回收站并恢复。

## 8. 阶段六：Worker 与异步处理

### 8.1 Worker 基础

- 初始化独立 Worker 入口。
- 连接 Redis。
- 配置 BullMQ 队列。
- 配置任务并发数。
- 配置任务重试次数。
- 配置任务超时时间。
- 配置任务失败记录。
- 配置临时文件清理定时任务（cleanup_temp，按 TEMP_FILE_TTL_SECONDS 清理过期临时文件）。
- 配置 Worker 执行时同步回写 processing_jobs 表状态（开始时 processing，完成/失败时 completed/failed，重试时更新 retry_count）。

验收标准：

- Worker 可以独立启动。
- API 可以创建队列任务。
- Worker 可以消费任务。
- 任务状态可以从 pending 更新到 completed 或 failed。
- processing_jobs 表状态与 BullMQ 队列状态保持同步。
- 临时文件超过 TTL 后可被自动清理。

### 8.2 元数据识别任务

- 实现资源类型识别任务。
- 实现 MIME 类型识别任务。
- 实现文件扩展名记录任务。
- 实现图片尺寸读取任务。
- 实现视频分辨率读取任务。
- 实现视频时长读取任务。
- 实现音频时长读取任务。
- 实现文件基础元数据更新任务。
- 实现元数据回写 resources 冗余字段（width、height、duration_seconds）。

验收标准：

- 图片资源有宽高。
- 视频资源有分辨率和时长。
- 音频资源有时长。
- 未识别类型归类为 other。

### 8.3 图片处理任务

- 使用 Sharp 生成图片缩略图。
- 保存缩略图文件记录。
- 更新资源预览状态。
- 处理图片格式异常。
- 处理超大图片限制。

验收标准：

- 图片上传后能生成缩略图。
- 图片处理失败时不影响原文件下载。
- 失败原因可在处理任务中查看。

### 8.4 视频处理任务

- 使用 FFmpeg 读取视频基础信息。
- 使用 FFmpeg 生成视频封面帧。
- 保存视频封面文件记录。
- 设置 FFmpeg 执行超时。
- 处理损坏视频失败状态。

验收标准：

- 视频上传后有封面图。
- 视频详情展示时长和分辨率。
- FFmpeg 失败时任务标记 failed。

### 8.5 音频处理任务

- 使用 FFmpeg 读取音频时长。
- 读取音频码率或格式信息。
- 更新资源元数据。
- 处理损坏音频失败状态。

验收标准：

- 音频详情能展示时长。
- 音频处理失败不影响原文件下载。

### 8.6 文本与 PDF 提取任务

- 提取 TXT 内容。
- 提取 Markdown 内容。
- 提取 JSON/CSV/XML 基础文本内容。
- 提取 PDF 文本（使用 pdf-parse，仅支持文本型 PDF，扫描型 PDF 留待后续 AI Worker）。
- 保存提取文本文件记录。
- 将提取文本写入 resources.search_vector 字段（通过 to_tsvector 合并标题、描述和提取文本）。
- 处理加密 PDF 或异常 PDF。
- Office 文档（docx/pptx/xlsx）第一版不提取文本，只记录文件元数据。

验收标准：

- 文本资源可预览。
- PDF 能提取基础文本。
- 文本和 PDF 内容可用于全文检索（search_vector 已更新）。
- PDF 失败时有明确失败原因。
- Office 文档不报错，正常归类为 document 类型。

### 8.7 任务重试与重新处理

- 实现失败任务重试接口（只重试 failed 状态的任务）。
- 实现单资源重新处理接口（可选：只重试失败任务，或清理派生文件后全部重新处理）。
- 实现批量重试失败任务。
- 实现任务日志查看。
- 重新处理时先清理已有派生文件再创建新任务，避免旧文件残留。

验收标准：

- 失败任务可手动重试。
- 资源详情能看到处理失败原因。
- 重试不会重复创建无效派生文件。
- 重新处理期间资源 processing_status 回到 processing，已有缩略图/封面仍可展示直到新文件生成。

验收标准：

- 删除和恢复行为符合预期。

### 14.2 彻底删除

- 创建彻底删除任务。
- 删除原文件。
- 删除缩略图。
- 删除预览文件。
- 删除提取文本。
- 删除资源标签关联。
- 删除集合资源关联。
- 删除处理任务记录。
- 删除资源文件记录。
- 删除资源记录。

验收标准：

- 彻底删除后资源不可恢复。
- 文件和数据库记录清理完整。
- 删除失败可重试。

### 14.3 一致性检查

归属 consistency module。

- 检查数据库有记录但文件不存在的情况。
- 检查文件存在但数据库无记录的情况。
- 检查临时目录中超过 TTL 的孤儿文件。
- 输出检查报告。
- 支持管理员手动触发检查。
- 清理操作通过 trash 和 storage module 完成，不直接删除文件。

验收标准：

- 能发现存储和数据库不一致问题。
